## 첫 수정 범위 (#47)

- 전체 분석 실패 및 확률 파싱 실패를 `status: failed`, `final: ERROR`로 구분한다.
- 기존 0/0/0 이력은 DB 원문 변경 없이 조회 시 실패로 표시한다.
- 실패 화면에서 확률, 시장 방향, 신뢰도, PDF/Telegram 내보내기를 제공하지 않는다.
- API에서도 실패 결과의 Telegram 내보내기를 차단한다.
- 한국어/영어/일본어 복구 안내를 제공하고 기술 오류는 접힌 상세 영역에 표시한다.
- 정상 횡보 결과와 일부 애널리스트 성공은 유지한다. 집계 설명에는 실제 성공 인원수를 사용한다.
- 테스트는 모의 AI와 임시 DB를 사용하며 실제 유료 호출 및 알림 발송은 하지 않는다.

## 검증 결과 (#47)

- `go test ./...`: 통과 (집계, 기존 이력 읽기, 저장/조회, API 응답 및 내보내기 차단 포함)
- `npm --prefix web test -- --run`: 117개 통과 (추가 분석 화면 테스트 4개 포함)
- `npm --prefix web run build`: 통과
- `git diff --check`: 통과
- 실행 중인 서버의 새 백엔드 반영 및 Chrome 재점검은 아직 하지 않았다.

## 데이터 준비 상태 개선 (#48)

- 상단 연결 표시는 서버 연결로 한정한다. 공급자 목록은 설정 목록이지 상태 점검 결과가 아님을 안내한다.
- 차트/Status에서 선택 종목과 시간봉의 가격 조회 상태를 공유 구성요소로 표시한다.
- 로딩, 저장된 캔들 없음, 조회 실패, 조회 성공을 구분한다. 실패/빈 상태에는 재조회와 종목 관리 경로를 제공한다.
- 조회한 캔들 개수(최대 200, 전체 DB 개수 아님), 마지막 캔들 시작 시각, 브라우저 조회 시각을 구분한다. 실제 수집 시각은 현재 기록되지 않음을 명시한다.
- 휴장이나 거래가 없는 상태를 단순 시간 차이로 장애 판정하지 않는다.
- 가격/신호 요청을 독립 실행하여 신호 실패가 정상 차트까지 오류 처리하지 않도록 한다.
- 선택/재조회 시 이전 데이터와 메타데이터를 지우고, 늦은 응답은 무시한다. Wyckoff/VIX 요청도 취소한다. 가격 데이터 없는 차트 축은 숨긴다.
- 저장소 미설정은 OHLCV API에서 빈 배열 대신 503을 반환한다.

검증: Go 전체 테스트 및 프런트엔드 128개 테스트 통과, 프로덕션 빌드와 diff 검사 통과. 신규 프런트엔드 11개 테스트로 빈 데이터/오류/정상/이전 응답 경합/시간봉 전환/3개 언어/신호 실패를 검증했다.

Chrome 플러그인에서 최신 프런트엔드의 SPCX 1H 차트 및 Status 화면을 확인했다. 캔들 132개와 마지막 시작 시각(2026-09-11 04:00 GMT+9)이 표시되며 조회 시각과 구분된다. 오류/빈 상태는 자동 테스트로 검증했다. 실행 중인 Go 서버는 재시작하지 않았으므로 API 503 변경은 현재 프로세스에 아직 반영되지 않았다.

## 종목 등록과 런타임 반영 (#49)

- 기존 검증 API로 이름·거래소를 확인해야 등록 가능하다. 공급자 실패와 확인 불가를 구분하고, 이전 입력의 늦은 응답은 무시한다.
- 중복 종목은 UI 및 API(409)에서 차단한다. 입력 공백·대소문자를 정규화한다.
- 등록 완료와 데이터 준비 완료를 구분하고, 조회/차트 이동을 제공한다.
- API의 저장 성공 이후 Runtime에 새 watchlist 스냅샷을 전달한다. 추가·활성/비활성·삭제에 모두 적용한다.
- 기존 수집기/파이프라인의 취소 및 종료를 기다린 후 최신 스냅샷으로 시작한다. 연속 변경은 최신 목록으로 합치고 세대 중첩을 금지한다. MCP 목록도 같은 스냅샷을 읽는다.
- HTTP 요청의 기존 타임아웃을 보존하면서 세대 취소를 전파하고, Binance WebSocket 대기를 해제한다. 파이프라인도 취소된 분석을 후속 발송하지 않도록 확인한다.
- Tiingo 수집 이력/제한 상태 파일은 유지한다. 공급자 목록에는 변경 전의 고정 종목 목록을 표시하지 않는다.
- 테스트: 추가/비활성/삭제 발행, 동시 등록, 저장 실패 시 미발행, 스냅샷 격리, 세대 중첩 방지, HTTP 취소/타임아웃, 검증 실패·중복·입력 경합.

## 초보자 모드 (#50)

- 새 사용자는 초보자 모드로 시작한다. 기존 저장 키와 명시적인 전문가 선택은 보존한다.
- 상단 모드 선택에서 바로 전환할 수 있으며 기존 설정 화면과 같은 상태를 사용한다.
- 초보자 모드에서는 고급 오버레이를 숨기고 비활성화한다. 전문가 모드에서 기존 오버레이 기능과 저장한 선택을 다시 사용할 수 있다.
- 시간봉·신호·ICT·SMC·FVG·OB·Wyckoff·TA·VIX 설명을 한국어/영어/일본어로 제공한다.
- Chrome에서 Tab으로 도움말 포커스 이동, Enter로 펼침, 전문가 전환 시 고급 기능 복원을 확인했다. 단위 테스트에서는 3개 언어와 포커스/선택·기존 설정 호환을 검증한다.

## 백테스트 준비 안내 (#51)

- `/api/backtest/readiness`는 실제 엔진이 사용할 전체 이력의 개수·시작/종료 시각과 최소 필요량을 반환한다. 차트의 200개 제한과 혼동하지 않는다.
- 최소 필요량은 엔진의 warmup + 2로 계산한다(현재 기본값 202). 부족한 데이터는 UI와 실행 서버 모두에서 차단한다(API 422).
- 익절/손절의 ATR 배수 기준과 기본값 2/1, 입력 범위를 설명한다. 데이터 준비 실패와 실행 실패를 구분한다.
- 거래 0건에서는 0% 성과처럼 보이는 통계 대신 원인과 다음 행동을 안내한다. 과거 모의 결과의 한계와 실주문이 아님을 안내한다.
- 종목·시간봉·조건 변경 시 이전 결과를 지우고 진행 중 요청의 늦은 응답을 무시한다.
- 정적 데모는 실제 백테스트 엔진이 없으므로 준비 불가(503)로 표시하며 실행을 활성화하지 않는다.
- 테스트: 0/200/201/202/500개 경계, 실제 API 조회·실행, 저장소 오류, 실행 실패, 거래 0건, 3개 언어. Chrome 격리 서버에서 132개 비활성 → 202개 활성 → 실제 테스트 엔진 거래 0건 흐름을 확인했다.

## 통합 검증과 반영 상태 (배포 전 기록)

- 프런트엔드: 146개 테스트 통과, 프로덕션 빌드 통과.
- 정적 데모 빌드도 별도 임시 출력 경로에서 통과했다(사용 중인 web/dist를 데모로 덮어쓰지 않음).
- Go: `go test ./...` 통과. `go test -race ./internal/collector ./internal/api ./internal/backtest ./internal/pipeline` 통과.
- `git diff --check` 통과.
- Chrome 검증은 임시 DB/모의 종목 검증 공급자/알림·주문 없는 별도 서버에서 수행했다. 사용자 watchlist나 실제 주문에는 영향을 주지 않았다. 수집 세대 교체는 자동 테스트로 검증했으며, 실제 외부 공급자에 연결한 종목 변경은 수행하지 않았다.
- 테스트 서버와 테스트 탭은 종료했다. 수동 프리뷰 테스트 프로세스는 검증 후 명시적으로 중단했으며, 정규 테스트 결과와 별개다.
- 새 백엔드 코드는 아직 사용자 서버 프로세스에 반영되지 않았다. 이번 버전 적용을 위한 서버 재시작은 한 번 필요하며, 적용 후에는 API/UI의 종목 변경마다 재시작할 필요가 없다.
- 커밋·푸시·릴리즈는 아직 수행하지 않았다.

## 후속 반영 원칙

이슈별 구현·회귀 테스트·화면 검증 후 상태를 갱신한다. 로컬 사용자 watchlist 및 실행 중인 서버는 임의로 변경/재시작하지 않는다. 커밋·푸시·릴리즈 완료 전에는 이슈를 완료로 닫지 않는다.

## 2026-09-12 전문가 오버레이 실제 사용 수정

- Chrome SPCX 4H에서 FVG·OB를 켜도 변화가 없음을 재현했다. 기존 구현은 캔들이 아닌 저장된 매매 신호의 zone 필드에 의존했고, 해당 종목의 저장 신호는 0건이었다. 선의 불투명도도 0.15로 낮았다.
- FVG·OB 시각화는 선택한 차트의 캔들로 계산하는 참고용 후보로 분리했다. 매매 엔진이나 주문 로직은 변경하지 않는다. 최근 최대 5개씩 표시하며 갭이 완전히 채워지거나 OB가 종가로 무효화되면 제외한다. OB는 형성 시점까지 최대 14개 봉의 평균 true range 대비 1.5배 impulse 조건을 사용한다. 엔진의 재진입 신호와 동일하지 않음을 화면에 명시한다.
- 청록 FVG/주황 OB 상하단 경계선을 형성 시점부터 최신 봉까지 표시한다. 상승 실선/하락 점선, 종류/방향/가격 라벨과 건수를 제공한다. 빈 데이터/패턴 없음도 표시한다.
- Zones는 W.Phase와 독립적으로 조회하며, Wyckoff/VIX 조회 실패·빈 데이터를 더 이상 묵살하지 않는다. ICT/SMC/TA 등은 저장 신호 필터임을 설명한다. 토글에는 aria-pressed를 추가했다.
- Chrome 실제 데이터: SPCX 4H FVG 2/OB 1, SPCX 1H FVG 3/OB 2, BTCUSDT 1H FVG 1/OB 4를 확인했다. FVG 해제 시 청록 경계가 사라지고 OB만 남는 화면 및 W.Phase를 끈 상태의 Zones 조회를 확인했다.
- 프런트엔드 전체 152개 테스트 통과. 후보 생성/무효화/상하 대칭/데이터 부족, 토글 제거, 시간봉 전환, Zones 단독 조회, VIX 빈 상태 회귀 테스트를 포함한다. 프로덕션 빌드로 로컬 서버에 프런트엔드를 반영했다. 백엔드 재시작 및 실제 분석·주문 실행은 하지 않았다.

## 추가 종목 및 설정 변경 검증

- 실제 Chrome/서버에서 TSLA 1H(200봉, FVG 5/OB 5), PLTR 4H(200봉, FVG 5/OB 1), ETHUSDT 1D(200봉, FVG 2/OB 3)를 점검했다. 후보 수는 당시 데이터 및 종류별 최신 5개 제한 기준이다.
- 추가 발견: 신호 API가 timeframe을 누락하여 목록에는 0건, 차트에는 다른 시간봉 마커가 표시될 수 있었다. API와 이력 응답에 timeframe을 포함하고 차트 마커도 선택 시간봉으로 필터링했다. 실제 재시작 후 ETHUSDT 1D 목록 4건, TSLA API 50건 모두 timeframe 포함을 확인했다.
- 추가 발견: AlertConfig의 JSON 태그 누락으로 UI가 빈 입력을 표시하고 저장 성공 후에도 수정값이 유지되지 않았다. UI 계약인 snake_case JSON 필드로 통일했다. GET→PUT→GET→YAML/런타임 일치 회귀 테스트를 추가했다.
- 격리 서버(임시 DB/설정, 발송기·주문 실행기 없음)에서 MSFT 등록/비활성화, AAPL 활성화/복원, 가격 알림 생성/삭제를 Chrome으로 확인했다. 종목 삭제 확인창은 브라우저 제어가 막혀 탭을 닫은 후 격리 API로 삭제했다. UI 확인창을 통한 삭제 완료는 미검증이다.
- 격리 주문 설정에서 enabled=false/kill_switch=true/플러그인 없음 상태를 유지하며 max_dispatched 3→5 저장/API 재조회→3 복원을 확인했다. 주문 체결이나 외부 발송은 테스트하지 않았다. 격리 서버에 피드백 DB·버전 저장소가 연결되지 않아 해당 오류/경고는 테스트 환경 제한이며 실제 주문 이력 검증을 의미하지 않는다.
- 수정된 격리 알림 설정은 점수 12→15, 쿨다운 4→6, 주식 TP 2→3 저장 후 Chrome 새로고침으로 유지 여부를 확인하고 원복했다. 실제 사용자 서버 설정은 변경하지 않았다.
- Go 전체 및 API/config race 테스트 통과. 추가 프런트엔드 회귀 테스트는 시간봉별 마커 분리를 검증한다. 프로덕션 빌드 통과.
- 백엔드는 `bin/chartter-server-settings`로 재시작하여 로컬 8080에 반영했다. watchlist/alert/execution YAML 해시가 재시작 전후 동일하며 실주문 비활성 상태를 유지했다. 로그: `logs/server-settings-20260912.log`.
- 검증용 탭과 두 수동 프리뷰 프로세스는 종료했다(명시적 interrupt 종료이며 정규 테스트 실패가 아님). 커밋·푸시는 아직 수행하지 않았다.
