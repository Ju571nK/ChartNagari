# v2.18.0.0 로드맵

작성일: 2026-11-15 · 기준: `main` `b33f514` (VERSION `2.17.0.0`)

## 목표

v2.18.0.0은 **라쿠텐 FX 데모 연결을 "읽기 전용으로 실제로 동작하는" 수준까지 끌어올리고**, 다음 단계인 주문 실행 전에
필요한 안전장치를 설계로 확정하는 릴리스다. 주문 실행, 실계좌, 유료 호스팅은 이번 버전에 넣지 않는다.

원칙(v2.17 개선 스택과 동일):

- PR 하나 = 검증 가능한 변경 하나. 테스트만으로는 검증 완료로 보지 않는다(실제 실행 증거 필요).
- HTF 패널티 자동 적용 금지, 알림 기본값(점수·쿨다운·일일 상한) 변경 금지.
- `config/settings.yaml`은 덮어쓰지 않는다. 비밀값은 `*.local.yaml`에만 둔다.

- [ ] `127.0.0.1:9300` WebRequest 허용 후 스냅샷 수신 확인 (실패 시 4014/4060 → `:80` 대안 검증 후 README 갱신)

**완료 기준:** 실제 데모 계좌의 계좌/주문이 signed `GET /v1/accounts`, `/v1/orders`로 조회되고, 그 증거(로그·스크린샷)가

### M4. FX 주문 실행 설계 확정 — 문서만

**왜:** 라쿠텐 주문 기능은 공통 실행 게이트웨이(리스크 한도·사이징·킬스위치)가 먼저다.
v2.18에서는 구현하지 않고 스펙만 합의한다.

- [ ] `docs/superpowers/specs/`에 설계 문서 작성:
  - v1 프로토콜에 `fx` asset class 추가 방식 (현재 `types.go:88`이 `stock`, `crypto`만 허용 — 하위 호환 영향)
  - 수량 단위(통화 단위 vs 로트), 최소 단위, 레버리지/증거금 검증 위치
  - 공통 게이트웨이: 플러그인별 최대 수량, 일일 주문 수, 손실 한도, 기존 kill switch와의 관계
  - EA 명령 큐(폴링) 방식, 결과 불명확 시 ticket/comment 기반 재조정
- [ ] `/plan-eng-review`로 리뷰 후 v2.19 구현 범위 확정

**완료 기준:** 리뷰를 거친 스펙 문서가 `main`에 있다. 코드 변경 없음.
