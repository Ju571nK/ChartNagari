# 주문 플러그인 개발키트 시작 안내

[English](en.md) · [日本語](ja.md) · [한국어](ko.md) · [문서 목록](README.md)

주문 플러그인은 증권사·거래소마다 다른 인증과 주문 API를 ChartNagari의
공통 규격에 맞춰 연결하는 **별도 실행 프로그램**입니다. 외부 개발자가
본체 코드를 고치지 않고 연동 기능을 만들 수 있도록 개발키트를 제공합니다.
브라우저 확장 프로그램이나 Codex 플러그인을 뜻하지 않습니다.

현재 v1은 **개발용 실험 단계**입니다. 플러그인을 설치하면 바로 실계좌 주문이
가능한 제품이나 플러그인 스토어가 아닙니다. 아래 안내는 현재 main 개발 기능을
기준으로 하며, 이전 정식 릴리즈에 모두 포함되어 있다는 뜻은 아닙니다.

## 일반 사용자: 지금 필요한가요?

차트, 가격 알림, 백테스트를 이용하는 데는 개발키트가 필요하지 않습니다.
특정 증권사를 연결하고 싶다면 먼저 그 증권사를 지원하는 어댑터가 실제로
제공되는지와 지원 범위를 확인해야 합니다. API 키를 입력하는 것만으로 임의의
증권사에 연결되지는 않습니다.

| 구분 | 현재 상태 |
| --- | --- |
| 기존 Alpaca 모의투자 웹훅 | 기존 주문 연동 경로 유지. 별도 실행기와 설정 필요 |
| Alpaca의 새 v1 API | 플러그인 정보·계좌·주문 조회만 지원 |
| 개발키트 모의 거래소 | 실제 증권사 연결 없이 주문·취소·장애 상황 개발/검증 |
| 설치·업데이트·웹 설정 자동 생성 | 아직 미구현 |
| 차트 신호 → 새 v1 주문 API | 아직 미연결 |
| v1 실거래·주문 정정·체결 이벤트 구독 | 아직 미지원 |

**실행 화면의 ‘플러그인 추가’는 기존 웹훅 실행기의 등록 메뉴입니다.**
개발키트의 모의 거래소 템플릿은 `/webhook` 실행기를 대신하지 않습니다.
이를 등록하거나 활성화해도 새 v1 경로로 주문이 전송되지 않으므로, 연결 확인
목적으로 실행을 켜지 마세요. 안내를 열거나 문서를 읽는 동작은 설정을 바꾸거나
주문을 활성화하지 않습니다.

## 외부 개발자: 무엇이 제공되나요?

- **공개 Go SDK:** 요청 인증, 입력 검증, 계좌·주문 API와 중복 요청 기록
- **OpenAPI 규격:** Go 외 언어에서 동일한 HTTP 규격을 구현할 수 있는 명세
- **독립 실행 템플릿:** 개인 YAML 설정, 기본 주문 비활성화, 로컬 실행
- **모의 거래소:** 정상 체결, 거절, 부분 체결, 대기, 응답 유실 시나리오
- **검사 도구:** 외부 플러그인에는 조회만 수행하는 `plugin-check`
- **자동 테스트:** 중복 요청, 재시작, 결과 불명, 부분 체결 후 취소 등의 검증

설정 스키마는 필요한 항목의 이름·유형을 선언하는 규격입니다. 아직 이 스키마를
읽어 웹 설정 화면을 자동으로 생성하거나 값을 저장하지는 않습니다.

## 1. 주문 없이 템플릿 실행하기

Go 1.26 이상이 필요합니다. 아래 명령은 macOS/Linux에서 **저장소 루트**를
기준으로 실행합니다. 이미 로컬 설정 파일이 있다면 복사로 덮어쓰지 마세요.

```bash
cp examples/order-plugin/config.example.yaml examples/order-plugin/config.local.yaml
chmod 600 examples/order-plugin/config.local.yaml
openssl rand -hex 32
```

생성한 비밀키를 `config.local.yaml`의 `plugin_secret`에 입력합니다.
비밀키를 커밋하거나 이슈·채팅·명령줄 인수에 붙이지 마세요.
`orders_enabled: false`는 그대로 둡니다.

```bash
go run ./examples/order-plugin -config examples/order-plugin/config.local.yaml
```

정상 실행 시 `127.0.0.1:9200`에서 시작하고 `order API enabled: false`라고
표시됩니다. 이 프로그램에는 실제 증권사 호출 코드나 실계좌 키가 없습니다.
중지하려면 실행한 터미널에서 `Ctrl+C`를 누릅니다.

## 2. 연결 규격을 조회로 확인하기

별도 터미널을 열고 저장소 루트에 `plugin-check.local.yaml`을 만듭니다.

```yaml
url: "http://127.0.0.1:9200"
plugin_id: example-paper
plugin_secret: "템플릿 설정과 동일한 공유 비밀키"
```

```bash
chmod 600 plugin-check.local.yaml
go run ./cmd/plugin-check -config plugin-check.local.yaml
```

성공 결과에는 `protocol: "1.0"`, `plugin_id: "example-paper"`, `accounts: 1`,
`read_only: true`가 포함됩니다. 이 명령은 플러그인 규격·계좌·주문 목록을 조회하며,
주문이나 취소를 보내지 않습니다. **검사 통과는 안전 인증이나 실거래 준비 완료가 아닙니다.**

연결되지 않으면 다음을 확인하세요.

- 실행 중인 주소/포트와 `url`이 같은지 확인합니다. `url`에는 `/webhook` 같은 경로를 넣지 않습니다.
- `plugin_id`와 공유 비밀키가 양쪽에서 일치하는지 확인합니다.
- 인증 오류라면 두 서버의 시각도 확인합니다. 허용 시각 차이는 ±300초입니다.
- 기존 웹훅 실행기는 v1 API를 제공하지 않을 수 있습니다. 검사 실패가 곧 기존 웹훅 고장은 아닙니다.

## 3. 내 증권사·거래소용 어댑터 만들기

1. [독립 실행 템플릿](../../examples/order-plugin/main.go)을 별도 프로젝트의 출발점으로 사용합니다.
2. `Broker` 인터페이스에 맞춰 인증, 계좌 조회, 주문 조회/전송을 구현합니다. 취소를 지원하면 `Canceller`도 구현합니다.
3. 종목 코드, 주문 단위, 계좌 권한과 지원 주문 종류를 해당 공급자 규칙에 맞춰 검증합니다.
4. 매니페스트에는 실제 구현한 기능만 선언합니다. v1에서 `replace`와 `events`는 `false`입니다.
5. 실제 계좌가 아닌 격리된 모의 환경에서 정상·오류·재시작 상황을 검증합니다.

Go 모듈 경로는 저장소 이름과 달리 아래와 같습니다. 오타가 아닙니다.

```text
github.com/Ju571nK/Chatter/pkg/brokerplugin
```

Go 이외 언어는 [OpenAPI 명세](../api/order-plugin-v1.openapi.yaml)와
[상세 개발 규격 — 영어](protocol.md)을 기준으로 구현합니다. 자동 생성한 HTTP
클라이언트에도 HMAC 서명 처리는 별도로 필요합니다. SDK는 증권사별 인증,
거래 권한, 수량 규칙을 대신 구현해 주지는 않습니다.

## 4. 모의 환경 검증과 안전 수칙

저장소에서 제공하는 테스트는 임시 DB와 가짜 거래소를 사용합니다.

```bash
go test -race ./pkg/brokerplugin/... ./internal/plugins/alpaca
```

직접 모의 주문을 시험할 때에만 **모의 거래소의** `orders_enabled`를 명시적으로
켜고 해당 프로그램을 재시작합니다. `SIM-FILL`, `SIM-REJECT`, `SIM-PARTIAL`,
`SIM-PENDING`, `SIM-TIMEOUT`으로 상황을 선택합니다. 요청 형식과 서명 예시는
[개발 규격의 HTTP 안내 — 영어](protocol.md#http-and-authentication)에 있습니다.

특히 다음을 지켜야 합니다.

- HTTP `202`는 체결 확인이 아닙니다. 응답의 주문 상태를 확인합니다.
- 결과가 `unknown`이면 원래 `client_order_id`로 조회합니다. 새로운 ID로 주문을 재전송하지 않습니다.
- 같은 ID로 같은 요청을 보내면 최초 기록을 돌려줍니다. 최신 상태는 GET 조회로 확인합니다.
- 재시작 후에도 요청 기록 DB를 유지합니다. 기록을 지우면 중복 방지의 근거가 사라집니다.
- 연결 확인이나 개발키트 실험을 위해 실계좌를 사용하지 않습니다.

## 로컬·원격·모바일에서는 어떻게 쓰나요?

플러그인은 로컬 PC 또는 원격 서버의 **별도 프로세스**로 실행합니다. 템플릿은
기본적으로 루프백 주소만 사용합니다. 원격 실행에는 HTTPS 역방향 프록시와
HMAC 인증, 접근 제한을 직접 구성해야 합니다. 인터넷에 포트만 열지 마세요.

모바일 사용자는 선택한 ChartNagari 서버를 이용하는 방향이며, 모바일 브라우저에
플러그인을 설치하거나 증권사 키를 저장하는 방식이 아닙니다. 현재 키트가 모바일의
실거래 화면이나 새 주문 전송 경로까지 제공한다는 뜻은 아닙니다.

프로세스 분리는 보안 샌드박스가 아닙니다. 검토한 플러그인만 제한된 권한으로
실행하고, 공유 비밀키는 플러그인마다 따로 사용하세요.

## 다음 단계

실제 제품 연동에는 계좌 선택, 수량 계산, 종목 매핑, 전역 주문 차단, 위험 한도,
체결 상태 확인과 감사 기록을 담당하는 공통 주문 경로가 더 필요합니다. 이후
플러그인별 웹 설정과 검증된 어댑터를 연결해야 합니다. Alpaca의 조회 전용 v1
API를 임의로 주문 가능하게 바꾸는 것으로 대체할 수 없습니다.
