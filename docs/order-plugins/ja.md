# 注文プラグイン開発キット スタートガイド

[English](en.md) · [日本語](ja.md) · [한국어](ko.md) · [ドキュメント一覧](README.md)

注文プラグインは、証券会社・取引所ごとに異なる認証や注文APIを
ChartNagariの共通仕様に接続する**独立した実行プログラム**です。
外部開発者が本体のコードを変更せずに連携アダプターを作れるよう、
開発キットを提供しています。ブラウザー拡張機能やCodexプラグインではありません。

現在のv1は**開発者向けの実験段階**です。インストール直後に実口座で
注文できる製品やプラグインストアではありません。このガイドは現在のmainを
対象としており、過去の正式リリースにすべての機能が含まれるという意味ではありません。

## 一般ユーザー：利用する必要はありますか？

チャート・価格通知・バックテストには開発キットは不要です。
特定の証券会社に接続したい場合、対応アダプターが実際に提供されているか、
何に対応しているかを先に確認してください。APIキーを入力するだけで、
任意の証券会社に接続できるわけではありません。

| 区分 | 現在の状態 |
| --- | --- |
| 既存のAlpacaペーパートレードWebhook | 既存の注文経路を維持。別プロセスの起動と設定が必要 |
| Alpacaの新しいv1 API | プラグイン情報・口座・注文の参照のみ |
| 開発キットのシミュレーター | 実際の証券会社に接続せず、注文・取消・障害を開発／検証 |
| インストール・更新・Web設定の自動生成 | 未実装 |
| チャートシグナル → 新しいv1注文API | 未接続 |
| v1実取引・注文訂正・約定イベント購読 | 未対応 |

**実行画面の「プラグイン追加」は、既存のWebhookアダプターの登録機能です。**
開発キットのシミュレーターテンプレートは、`/webhook`アダプターの代わりにはなりません。
登録・有効化しても新しいv1経路で注文は送信されないため、接続確認のために
実行を有効にしないでください。案内を開いたり文書を読んだりする操作では、
設定の変更や注文の有効化は行われません。

## 外部開発者：何が提供されますか？

- **公開Go SDK：** リクエスト認証、入力検証、口座・注文API、重複リクエストの永続記録
- **OpenAPI仕様：** Go以外の言語で同じHTTP仕様を実装するための定義
- **独立実行テンプレート：** 非公開YAML設定、初期状態で注文無効、ローカル実行
- **模擬取引所：** 正常約定、拒否、部分約定、待機、応答消失のシナリオ
- **検査ツール：** 外部プラグインに対して参照のみを行う`plugin-check`
- **自動テスト：** 重複、再起動、結果不明、部分約定後の取消などの検証

設定スキーマは必要な項目の名前・型を宣言します。現時点では、このスキーマから
Web設定画面を自動生成したり、値を保存したりする機能はありません。

## 1. 注文を無効にしてテンプレートを起動する

Go 1.26以上が必要です。以下のコマンドはmacOS/Linuxで、
**リポジトリのルートディレクトリ**から実行してください。
既にローカル設定ファイルがある場合、コピーで上書きしないでください。

```bash
cp examples/order-plugin/config.example.yaml examples/order-plugin/config.local.yaml
chmod 600 examples/order-plugin/config.local.yaml
openssl rand -hex 32
```

生成したシークレットを`config.local.yaml`の`plugin_secret`に入力します。
コミットしたり、Issue・チャット・コマンドライン引数に貼り付けたりしないでください。
`orders_enabled: false`は変更しません。

```bash
go run ./examples/order-plugin -config examples/order-plugin/config.local.yaml
```

正常に起動すると、`127.0.0.1:9200`で待ち受け、`order API enabled: false`と
表示されます。このプログラムには実際の証券会社への接続コードや実口座のキーは
含まれません。終了するには、起動したターミナルで`Ctrl+C`を押します。

## 2. 参照だけで接続仕様を確認する

別のターミナルを開き、リポジトリのルートに`plugin-check.local.yaml`を作成します。

```yaml
url: "http://127.0.0.1:9200"
plugin_id: example-paper
plugin_secret: "テンプレート設定と同じ共有シークレット"
```

```bash
chmod 600 plugin-check.local.yaml
go run ./cmd/plugin-check -config plugin-check.local.yaml
```

成功した結果には、`protocol: "1.0"`、`plugin_id: "example-paper"`、`accounts: 1`、
`read_only: true`が含まれます。このコマンドはプラグイン仕様・口座・注文一覧を
参照するだけで、注文や取消は送信しません。**検査合格は安全認証や、
実取引の準備完了を意味しません。**

接続に失敗した場合は、次を確認してください。

- 起動中のアドレス・ポートと`url`が一致しているか確認します。`/webhook`などのパスは含めません。
- 両側の`plugin_id`と共有シークレットが一致しているか確認します。
- 認証エラーの場合は、両サーバーの時刻も確認します。許容される時刻差は±300秒です。
- 既存のWebhookアダプターはv1を提供していない場合があります。検査失敗が既存Webhookの故障を意味するとは限りません。

## 3. 証券会社・取引所用アダプターを作る

1. [独立実行テンプレート](../../examples/order-plugin/main.go)を別プロジェクトの出発点にします。
2. `Broker`に合わせて認証、口座、注文参照・送信を実装します。取消に対応する場合は`Canceller`も実装します。
3. 銘柄コード、数量単位、口座権限、対応注文種類を、提供元のルールに沿って検証します。
4. マニフェストには実装済みの機能だけを宣言します。v1では`replace`と`events`は`false`です。
5. 実口座ではなく、隔離された模擬環境で正常動作・エラー・再起動を検証します。

Goモジュールのパスはリポジトリ名と異なります。誤記ではありません。

```text
github.com/Ju571nK/Chatter/pkg/brokerplugin
```

Go以外の言語では、[OpenAPI仕様](../api/order-plugin-v1.openapi.yaml)と
[詳細技術仕様（英語）](protocol.md)に従って実装します。
自動生成したHTTPクライアントにもHMAC署名が別途必要です。SDKが証券会社固有の
認証、取引権限、数量ルールを代わりに実装するわけではありません。

## 4. 模擬環境での検証と安全上の注意

リポジトリのテストは一時DBと模擬取引所を使用します。

```bash
go test -race ./pkg/brokerplugin/... ./internal/plugins/alpaca
```

手動で模擬注文を試す場合に限り、**シミュレーター側の**`orders_enabled`を
明示的に有効にし、そのプログラムを再起動します。
`SIM-FILL`、`SIM-REJECT`、`SIM-PARTIAL`、`SIM-PENDING`、`SIM-TIMEOUT`で
シナリオを選びます。リクエスト形式と署名の例は
[HTTP仕様（英語）](protocol.md#http-and-authentication)を参照してください。

特に次を守ってください。

- HTTP `202`は約定確認ではありません。レスポンス内の注文状態を確認します。
- `unknown`の場合は元の`client_order_id`で照会します。新しいIDで注文を再送しないでください。
- 同じIDで同じリクエストを送ると、最初の記録が返ります。最新状態はGETで照会します。
- 再起動後もリクエスト記録DBを保持します。削除すると重複防止の根拠が失われます。
- 接続確認や開発キットの実験に実口座を使用しないでください。

## ローカル・リモート・モバイルでの利用

プラグインはローカルPCまたはリモートサーバーの**別プロセス**として実行します。
テンプレートは初期状態でループバックアドレスだけを使用します。
リモート実行にはHTTPSリバースプロキシ、HMAC認証、アクセス制限を自分で
設定する必要があります。単にポートをインターネットへ公開しないでください。

モバイルでは、選択したChartNagariサーバーを利用する方針です。
モバイルブラウザーにプラグインをインストールしたり、証券会社のキーを保存したり
する方式ではありません。現在のキットが、モバイル用実取引画面や新しい注文送信経路まで
提供しているという意味ではありません。

プロセス分離はセキュリティサンドボックスではありません。レビュー済みのプラグインだけを
制限された権限で実行し、共有シークレットはプラグインごとに分けてください。

## 次の段階

製品への連携には、口座選択、数量計算、銘柄マッピング、全体の注文停止、
リスク上限、約定状態の照合、監査記録を担う共通の注文経路が必要です。
その後にプラグイン別のWeb設定と検証済みアダプターを接続します。
Alpacaの参照専用v1 APIで注文を有効にするだけでは、これらの代わりにはなりません。
