# v2.17.0.0. Alert drops, Discord review, and safer paper closes

This source release shows why an alert did not send, adds a Discord review
link, and asks before a paper close. Keep your existing configuration and
database. Automatic HTF penalty calibration is not in this release. Paid
hosting is not in this release.

## See why an alert did not fire

Open Status. Each hard drop is one row. The row is keyed by symbol, rule,
timeframe, direction, reason, and sender. `GET /api/alert-drops` returns the
newest rows. A repeated cooldown updates that row. A send failure stores the
sender name and the fixed phrase "delivery failed". The raw error stays in
the log.

When alert drop recording is on and a symbol has no rows, the status line
stays. A second line names score, cooldown, filter, and delivery
suppressions. An empty list means nothing was suppressed recently. When
recording is off, Status says that recording is off.

## Review a Discord alert

A Discord webhook cannot host Took or Skipped buttons. When
`CHARTNAGARI_URL` is a usable origin, the embed adds a `Took / Skipped` link
to My Trades Pending. Pending includes Telegram `PENDING` stubs and signals
with no mark row. The page uses the existing mark buttons.

Set `CHARTNAGARI_URL` to an origin a phone can open. A loopback value warns
at Discord startup. Change it in Settings, then restart the main server.

## Close a paper position

The Paper tab can close an open position as `CLOSED_MANUAL`. Closing asks
for confirmation first. Cancel leaves the position open. Confirm marks it
`CLOSED_MANUAL`. A positive request price is the exit price. Otherwise the
latest bar close is the exit price.

## Match execution settings to the server

The Execution tab uses the server contract. Plugins are keyed by `id`. The
dedup window is `dedup_window_sec`, in seconds. `symbol_map` is an optional
flat map from symbol to ticker. Plugin edit, delete, toggle, and dedup
window saves reach the server.

## Read the version from the VERSION file

The startup log field `version` reads `VERSION` through
`api.ProductVersion()`. MCP `initialize` reports `serverInfo.version` from
that file. The runtime image copies `VERSION` next to the server binary.
`get_analysis` and `get_ohlcv` list 1W, 1D, 4H, 1H, and 15M when the
timeframe is invalid.

## Run the same checks as CI

Pull request CI runs `vitest run` on the frontend job and `go test -race
./...` on the Go job. Local `make test` uses the race detector. Run `cd web
&& npm run test:ci` for the same non-watch Vitest command as CI.

## Leave calibration and hosting unchanged

HTF opportunity diagnostics stay on 1H and 4H. This release leaves HTF
penalty calibration, alert scores, cooldowns, daily caps, and order
execution unchanged. Paid hosting is not included. The restored personal
AWS runbook documents an existing self-hosted layout. It is not a hosted
product. Forex 15-minute collection stays opt-in, as in v2.16.0.0.

## Upgrade notes

Keep your existing configuration files and database. Upgrade the source,
rebuild the frontend, and restart the server. Do not replace the
configuration or the database.

## Verification and distribution

Release validation passed `go test ./...` and `npm --prefix web test -- --run`.
Vitest reported 244 tests passed in 35 files. This is a source release. It
contains no bundled binaries and no automatic-trading capability.
