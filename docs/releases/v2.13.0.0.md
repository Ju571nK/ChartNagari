# v2.13.0.0 — Web Settings & Clearer Charts

ChartNagari now makes chart overlays easier to inspect and application settings
easier to manage from the browser. This release includes the changes since
v2.12.0.0, plus a refreshed English, Korean and Japanese README with new captures.

## Highlights

- **Web-managed YAML settings:** configure the server, database, data providers,
  notifications, AI/Ollama, MCP bridge and Alpaca paper adapter in Settings.
  Secret fields are masked, removal is explicit, and writes are atomic with
  owner-only permissions. API authorization stays in tab memory.
- **Clearer expert charts:** FVG/OB candidate ranges are derived from candles,
  with distinct colors and counts, independently of stored engine signals.
  Signal markers respect the selected timeframe. Candidates are not trade signals.
- **More helpful feedback:** beginner guidance, missing-data/retry states,
  backtest history-readiness checks and explicit analysis failure messages.
- **Reliability fixes:** alert settings persist correctly, saved watchlist changes
  update collectors, VIX indices use Yahoo instead of Tiingo, and the display-mode
  label no longer overlaps its control.
- **Refreshed introduction:** a new 12-second sample-data GIF and original
  screenshots; architecture and installation details now live in separate guides.

## Upgrade notes — read before restarting

1. Back up your existing configuration and database securely. Do not overwrite
   `config/settings.yaml` with the example or commit files containing secrets.
2. Settings without `version: 1` migrate recognized application keys once, using
   process environment, then `.env`, then existing YAML precedence. Run
   `go run ./cmd/server --migrate-settings-only` from the project directory with
   the old deployment environment to migrate without starting services.
3. After migration, runtime application settings use YAML and defaults, **not
   environment overrides**. Keep the version marker. Separately configured
   sidecars need their credentials entered in YAML before restarting.
4. General settings require a server restart; MCP and Alpaca processes must be
   restarted separately. Saving credentials does not enable execution or place orders.
5. For Docker, set the YAML server host to `0.0.0.0`, port to `"8080"` and database
   path to `./data/chart_analyzer.db`; keep the published host port loopback-only.

See [Settings and migration](https://github.com/Ju571nK/ChartNagari/blob/v2.13.0.0/SETTINGS.md)
and [Getting started](https://github.com/Ju571nK/ChartNagari/blob/v2.13.0.0/docs/getting-started.md).

## Scope and limitations

- README captures use bundled sample data, not a live feed. Server-backed features
  require a self-hosted server. The static demo may show a reconnecting indicator.
- VIX is a market-volatility proxy, not per-instrument options implied volatility.
- YAML secrets remain plaintext on disk. Protect files and backups; do not expose
  an unauthenticated server to the internet.
- Source release, matching the previous release's distribution format. No bundled
  binaries or production deployment are included.
