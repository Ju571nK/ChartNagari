# v2.17.1.0. Token-protected backups and a read-only Rakuten demo bridge

This source release closes an unauthenticated read path for backups and
settings, adds an experimental read-only Rakuten FX MT4 demo bridge, and
changes the default alert configuration. Keep your existing configuration and
database. Order execution, automatic HTF penalty calibration, and paid hosting
are not in this release.

## Protect backups and settings with the API token

When `server.api_token` is set, these reads now need
`Authorization: Bearer <token>` even when `remote_access` is off:

- `GET /api/backup/db`
- `GET /api/settings/export`
- `GET /api/settings/config` and its legacy alias `GET /api/env/config`
- `GET /api/connection` (unchanged)

Before, a server with `remote_access` off answered the first three without the
token. A reverse proxy in front of that server could hand out the whole SQLite
database. Other local reads stay anonymous. With no token configured, nothing
changes.

In the web UI, open Settings and use **Authorize changes** once per tab. The
Settings page reloads after a successful authorization when its first read was
refused. Backup and export downloads send the token after authorization.

## Read a Rakuten FX MT4 demo account

`cmd/plugin-rakutenfx` is an experimental order plugin v1 adapter. The bundled
MT4 EA (`ChartNagariBridge.mq4`) pushes demo account and order snapshots over
loopback. The adapter serves them through the signed `GET /v1/accounts` and
`/v1/orders` endpoints. It refuses live accounts and other servers. It does not
submit or cancel orders. The EA has not yet been compiled and checked against a
real Rakuten MT4 terminal; treat the bridge as unverified.

The Execution tab adds an order-plugin developer guide in English, Korean, and
Japanese. The plugin kit docs moved to `docs/order-plugins/`. The
`examples/rakuten-mt4-bridge` simulator placeholder is removed.

## Default configuration changes

The tracked default files changed:

- `config/alert.yaml`: `score_threshold` 12 → 10, `cooldown_hours` 4 → 2.
- `config/watchlist.yaml`: ETHUSDT and ^VIX removed, SPCX and USDJPY added.

If you track the repository with `git pull` and never edited these files,
you get the new values, so alerts become more frequent and ^VIX is no longer
collected. To keep the old behavior, restore the previous values in those
files after upgrading.

## Upgrade notes

Keep your existing configuration files and database. Upgrade the source,
rebuild the frontend, and restart the server. If you set an API token, authorize
in Settings before using backup, settings export, or the Settings page.

## Verification and distribution

Release validation passed `go test ./...` and `npm --prefix web run test:ci`.
The token rule was also checked against a running server with `curl`. This is a
source release. It contains no bundled binaries and no automatic-trading
capability.
